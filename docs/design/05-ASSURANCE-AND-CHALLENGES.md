## Five end-to-end journeys, ranked by review value

1. **Confident mistake → defensible decision.** Open duplicate mileage or masked provider-ID discrepancy, show printed source/extracted reading/supplied computation separately, inspect exact field/page and independent check, record verification and source-supported decision, reload. Pass only if original/history remain intact and estimated effect is explicit. This proves the core workpaper idea rather than an attractive summary.
2. **Change → independent review → stale conflict.** Separate preparer/reviewer sessions inspect changed-since, blocking note and content-bound sign-off. Save a material change elsewhere. Verify stale approval is gone, stale write receives a conflict, safe rationale survives and deliberate resubmit records a new revision. Include source-only version change and role/API denial.
3. **Dense record → source → tie-out.** Filter/page the full sales population, inspect one lot and reconcile totals; compare one asset across Federal/CA/AMT, then examine state allocation and missing basis. Pass only when summaries and full detail agree and uncertainty remains visible.
4. **Unknown fact → intended respondent → evidence.** Ask a targeted client/colleague question, show deadline/notification, attempt wrong-recipient response, answer as intended persona, link durable answer into a judgment/diligence record and reload. No outside communication or invented answer is implied.
5. **Authorized review → preserved filing → later notice.** Use an isolated simulation fixture to complete current approvals/joint attestations, freeze, simulate rejection/correction and open amendment while retaining parent. Download client copy/offline notice record; disconnect network and verify all promised evidence bytes/anchors/hashes, then inspect next-year handoff/planning history. Include a concurrent-export test before calling F07 complete under sharing.

Run those journeys on the final shared deployment, including a restart/reload, independent sessions and one failure path each. Existing offline synthetic paths remain useful regression evidence, but the final video must not make an unresolved real review workspace appear professionally completed. The five-task observation protocol is a design recommendation for the PDF's CPA/new-hire bar; the PDF does not prescribe a sample size or measurement method.

## Alternative and tradeoff

**Strongest alternative:** implement genuine per-user login, membership, role-specific DTOs, PostgreSQL and private object storage before any hosted demo. This yields a stronger security/collaboration demonstration and accommodates stateless hosting. It also adds migration/session/storage work and can displace the central review-UX and submission work. For this fictional one-household assignment, a controlled evaluator gate with a separately disclosed role simulator and a durable single-instance repository is defensible, provided its actual limits are explicit and all role/action/invalidation invariants still work. It must never be presented as real multi-client authorization.

I favor **a strict release gate over a wholesale rebuild**: keep the monolith, choose persistence according to the actual host, fix snapshot/export consistency and interaction trust defects, then run the core journeys and all atomic feature checks against that deployment. Do not add a graph/vector database, queue, WebSocket service, autonomous tax agent or broad onboarding platform merely to make the diagram look sophisticated. A runtime upgrade or repository adapter should be narrowly tested; it does not erase the need for the hosted acceptance run.
